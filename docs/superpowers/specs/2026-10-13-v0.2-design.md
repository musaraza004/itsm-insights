# v0.2 Design: business hours, clock pausing, FCR, reopen and escalation

Status: proposed, 2026-10-13. Builds on v0.1 (commit `b6d78fc`).

## Goal

Make reported SLA performance match how service desks actually measure it:

1. A ticket opened Friday 18:00 with a 4-hour business-hours target must not breach on Saturday.
2. Time in statuses such as "Waiting for customer" must not count against the resolution SLA.
3. Report first-contact resolution (FCR), reopen rate and escalation rate.

## Decisions

### Calendars

- New config section `calendars:`. Each named calendar has `timezone` (defaults to the
  top-level `timezone`), `days` (names `mon`..`sun`, ranges like `mon-fri` allowed),
  `hours` (`"HH:MM-HH:MM"`, same-day only) and `holidays` (list of dates).
- `24x7` is built in and cannot be redefined. An SLA policy naming an undefined calendar is a
  config error that lists the calendars that are defined.
- Working windows are built in the calendar's local timezone each day, then compared in UTC, so
  daylight-saving days get the correct number of hours.
- Overnight windows (`22:00-06:00`) are rejected in v0.2 with a clear error. Teams running
  night shifts can use `24x7` until a later version supports them.

### Status history

- A second, optional input: a long-format history CSV/JSON, one row per field change:
  `ticket_id, changed_at, field, value`. Column names are mapped with `history_columns:`.
- Recognised fields: `status`, `assignee_group`, `assignee` (case-insensitive). Other fields are
  dropped, so a full Jira-style changelog can be passed as-is.
- The first event for a field is that field's initial value; later events are changes.
- History rows for tickets not in the ticket export are ignored and counted in a warning.

### Clock pausing

- Pause statuses = `pause_statuses` plus `resolved_statuses` (default `Resolved`, `Closed`), all
  compared case-insensitively. Time spent resolved before a reopen therefore does not count.
- A status holds from its event until the next status event for that ticket; the last status
  holds until the analysis time.
- **Pausing applies to the resolution clock only.** The response clock measures how quickly a
  person first answered; waiting on the customer cannot happen before that.
- SLA elapsed = working time on the policy's calendar between start and stop, minus working time
  inside pause intervals. Pauses are clipped to the ticket's own start and stop.
- With no history file, clocks run without pausing and the existing warning says so.

### FCR, reopen, escalation

Computed only for tickets that have history (others are excluded from the denominator and counted
in a warning):

| Metric | Numerator | Denominator |
| --- | --- | --- |
| FCR rate | resolved, never reopened, never escalated, no reassignment | resolved tickets |
| Reopen rate | tickets with at least one resolved → non-resolved status change | tickets resolved at least once |
| Escalation rate | tickets with at least one move to a higher tier in `escalation_tiers` | all tickets |

- Reassignment = any change of `assignee_group` or `assignee` after its first value.
- Escalation tiers are an ordered list in config, e.g. `["L1 Service Desk", "L2 Infrastructure",
  "Vendor"]`. Lateral or downward moves are not escalations. Groups not in the list are ignored
  for escalation (still reassignments).
- Escalation paths (`L1 Service Desk -> L2 Infrastructure: 412`) are reported too.

### Generator

- Emits a history file next to the tickets. P1 uses `24x7`; P2–P4 use a `business` calendar
  (Mon–Fri 08:00–18:00 Europe/London, UK bank holidays) matching `examples/sla.yaml`.
- Plants waiting periods, reopens, escalations and reassignments, and records truth columns.
  Truth is computed from the generator's own active segments with `working_seconds`, without
  using the pause or SLA code, and the tests require exact agreement.

### Interfaces

- CLI: `analyze tickets.csv --history history.csv`. `generate-demo` writes
  `<out stem>_history.csv` as well.
- Web app: optional second file input for history.
- MTTR stays wall-clock (what the requester experiences). SLA elapsed columns are business time.

## Out of scope for v0.2

Overnight shift calendars, per-priority pause rules, repeat incidents, heatmaps, Jira/ClickUp
loaders (v0.3).
