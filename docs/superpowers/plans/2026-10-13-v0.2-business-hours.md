# v0.2 Business Hours, Clock Pausing and Handling Metrics: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** SLA elapsed time that respects working hours, holidays and "waiting" statuses, plus FCR, reopen and escalation rates from status history.

**Architecture:** A `calendars` module measures working time between instants. A long-format history file (`ticket_id, changed_at, field, value`) is turned into per-ticket pause intervals and handling facts by a `timeline` module. `sla.evaluate` subtracts working time inside pauses from working time on the policy's calendar. Handling rates are computed from the facts. The generator emits history with planted outcomes so tests can check exact recovery.

**Tech Stack:** Python 3.11+, pandas, Pydantic v2, Typer, pytest; Pyodide web app.

**Spec:** `docs/superpowers/specs/2026-10-13-v0.2-design.md`

## Global Constraints

- No new runtime dependencies (pandas, typer, pydantic, pyyaml, rich, tzdata only).
- Python >= 3.11; must also run under Pyodide 0.27.7 (Python 3.12) in the web app.
- CLI output stays ASCII (Windows cp1252 consoles).
- ruff line length 100; `ruff check` and `ruff format --check` clean.
- Never commit real ticket data; tests use synthetic fixtures only.
- v0.1 behaviour is unchanged when no calendars and no history are configured.

## Review Focus

1. Ticket created outside working hours (Saturday): clock starts Monday at opening time, so a Monday 09:10 response to a Saturday ticket is 10 minutes. Test in Task 1.
2. Daylight-saving day: a 09:00-17:00 window on the clocks-change Sunday is 8 hours, computed in local time. Test in Task 1.
3. History rows for unknown tickets, and tickets with no history: ignored and counted; no pauses. Tests in Tasks 4 and 6.
4. History events before `created`, or unsorted: sorted, and pauses are clipped to the ticket's own clock. Tests in Tasks 3 and 5.
5. Ticket still paused at the analysis time ("Waiting for customer", open): pending, not breached, because waiting time does not count. Test in Task 5.

### Task 1: Working-time calendars

**Files:** Create `src/itsm_insights/calendars.py`; Test `tests/test_calendars.py`.

**Produces:**
- `class TwentyFourSeven` (name `"24x7"`), `class BusinessCalendar(name, timezone, workdays: frozenset[int], opens: time, closes: time, holidays: frozenset[date])`.
- Both: `working_seconds(start: Timestamp, end: Timestamp) -> float`, `add_working_time(start: Timestamp, seconds: float) -> Timestamp`.
- `active_seconds(start, end, calendar, pauses=()) -> float`: working time minus working time inside the (merged, clipped) pauses.
- `TWENTY_FOUR_SEVEN` singleton.

- [ ] Tests (UTC-equivalent dates in January, Europe/London): same-day 10:00-12:00 = 2h; Fri 16:00 -> Mon 10:00 = 2h; weekend span = 0; Saturday creation, Monday 09:10 response = 10m; end <= start = 0; holiday skipped (24 Dec 16:00 -> 28 Dec 10:00 with 25 Dec holiday = 2h); two weeks = 80h; DST Sunday 2026-03-29 with Sunday as a workday = 8h; `add_working_time(Fri 16:00, 4h)` = Mon 12:00; `add_working_time(Sat, 0)` = Mon 09:00; round trip `working_seconds(s, add_working_time(s, d)) == d`; closes <= opens and empty workdays raise; naive timestamps raise; `active_seconds` subtracts only in-hours pause time and clips pauses outside [start, end].
- [ ] Run, see failures. Implement with per-day windows built in local time (cached), compared in UTC. Run, pass. Commit.
